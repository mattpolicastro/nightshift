## 1. specloop

- [x] 1.1 Add `action` (kind, headline, why, command from `messages.for_pause`, plus the `act` verbs that fit the pause per design.md's table) to every paused run in `specloop status --json`, with marked tests covering `run-actions/actions-in-status/gate-action-described` and `run-actions/actions-in-status/running-run-has-no-action`
- [x] 1.2 Add `specloop act <change> <verb> [--note TEXT] --json`, which reloads the run, refuses a verb not listed for its current pause, an unknown change or a note over 2,000 characters, and otherwise does exactly what the matching command would, printing a version-1 outcome, with marked tests covering `run-actions/act/resume-with-a-note` and `run-actions/act/wrong-verb-refused`
- [x] 1.3 Fix this finding from section 1's review: In specloop/serve.py:121–125, pass_once calls lift_due before acquiring the run lock, using previously loaded state. If act abort completes after that snapshot was loaded for a due infra or usage_limit pause, lift_due overwrites aborted with running and restarts the run. It can similarly discard a resume note. Reproduced with in-memory persistence. Acquire the lock and reload before checking or changing automatic pauses. (integration:act locking does not protect against supervisor auto-resume)
- [x] 1.4 Fix this finding from section 1's review: specloop/cli.py:429 advances the local branch to the archive before pushing remotely or marking the PR ready. If either external operation fails, act returns refused while the run remains at human_checks. Every retry then fails at line 420 because the original tasks.md no longer exists. Status also fails for the entire run list because its archive lookup only handles done runs. Reproduced with injected network failure. Make finish restartable from the archived commit and keep status readable during recovery. (input:finish encounters a network failure after committing the archive locally)
- [x] 1.5 Fix this finding from section 1's review: act always passes no_run=True (specloop/cli.py:462), so _resume returns before _sync. The supervisor subsequently invokes run_cmd, which also never synchronizes the source branch. Consequently, source edits made to resolve a requested or blocked pause are ignored, although direct resume imports them. The CLI-path check confirmed zero sync calls through act plus run, versus one through direct resume. Preserve the source synchronization when deferring execution to serve. (input:human commits source-branch corrections before resuming through act)
- [x] 1.6 Fix this finding from section 1's review: For an admitted run without a recorded PR, _publish unconditionally calls gh pr create (specloop/cli.py:398). If GitHub creates the PR but the response is lost, or the process exits before ctx.pause saves state, the next act publish repeats creation and fails because the PR already exists. The run remains at ready_to_publish despite recovery of the service. Reconcile an existing PR for the branch before retrying creation and persist the recovered URL. (input:GitHub creates a PR but publication is interrupted before its URL is persisted)
- [x] 1.7 Fix this finding from section 1's second gate review: the direct `accept`, `abort`, `publish` and `finish` commands in `specloop/cli.py` do not take the run lock that `act` holds, so a direct `publish` can overwrite an `act abort` saved during its push. Make every state-changing command acquire the run lock and reload before it checks or changes state (keeping the internal helpers `act` uses), with regression tests for a direct command racing `act`
- [x] 1.8 Fix this finding from section 1's second gate review: `accept` lands the candidate (`loop._land`, around `specloop/cli.py:314`) before it clears the pause, so a process that stops in between leaves a landed task under its old stuck or needs_human pause, and every later `act accept` fails the candidate_base check. Make acceptance recognise a completed landing and finish the transition on retry, with a regression test that interrupts between the two
