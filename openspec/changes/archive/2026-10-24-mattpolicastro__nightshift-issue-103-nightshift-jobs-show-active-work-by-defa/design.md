## Context

`nightshift/cli.py::_jobs` prints every row from `specloop_job.list_jobs` and assigns every finished row the same uncertain delivery wording. `list_jobs` inventories attempt directories independently of receipts; `Job.state` describes execution. Status, stop, release and deployment checks also consume it, so filtering the shared inventory would break other consumers.

`nightshift/specloop_job.py::compact_delivered(path, receipt)` already validates exact receipt/job identity, terminal result, request context, keyed revision provenance, idle lifetime lock, stop absence, file ownership and symlinks. It journals cleanup, preserves request mtime and retains result/control evidence. Unsafe idea targets can be retained with diagnostics while other proven artifacts are compacted. `resume_cleanup` can use journals after receipt replacement for an authorized daemon visit; the manual pass must not use that weaker receipt requirement.

No AGENTS.md is present in this checkout or its ancestor directories. README points to CLAUDE.md, whose preservation and compatibility guidance applies. The four requested acceptance-test names are absent in this snapshot and must be added. Existing tests cover offline inventory, error visibility, stop/release, compaction refusal, interrupted cleanup, denied authorization and keyed provenance.

## Goals / Non-Goals

Make default inventory useful, give receipt-based delivery wording, and provide a bounded local operation for safely reclaiming older delivered logs/inputs. Preserve historical discovery, ordering, offline operation, execution states and unrelated assertions.

Do not change daemon delivery or cleanup call sites, GitHub eligibility, receipt contents, round IDs, process signaling, retention outside #9's artifacts, report schemas, or supervisor behavior. No age cutoff, background scanner, permanent migration marker, dependency or Markdown parser is needed.

## Decisions

1. Keep `list_jobs(state_dir)` unfiltered and behavior-compatible for existing callers. Add an optional keyword `include_delivery=False`; only inventory CLI calls opt in. Extend `Job` with defaulted receipt-display metadata, without changing `state` or persisted schemas. Resolve the item receipt as `job.directory.parent.with_suffix(".json")`; read it once per item per invocation. Missing receipts and absent/false `delivered` mean not delivered. Only JSON boolean true means delivered. Malformed/non-object/unreadable/symlinked receipts or non-boolean declared delivery flags produce diagnostics, keep affected rows visible, and make inventory exit 1. Do not follow receipt symlinks or create state. Missing legacy receipts are normal and cause no diagnostic. Other consumers retain receipt-independent behavior.

2. Display completion and deletion eligibility separately. A finished row with a valid item receipt marked delivered reads `delivered`, including historical attempts when that receipt names a successor or has no job field. This is the requested item-level display convention, not proof that each attempt delivered independently. All other finished rows read `finished (delivery pending)`. No inference comes from age, result existence, collection, merged PRs or cleanup journals. Other execution states are not relabeled delivered. Receipt replacement can change older rows' display; `--all` retains access, and the compactor independently requires exact attempt provenance.

3. Filter only in `_jobs` after complete inventory and diagnostics are collected. Retain starting, running, stopping, stopped and finished-undelivered rows, plus all rows with record/receipt diagnostics. Starting is the startup phase of active work. Overdue is a timing condition on active work, not a new persisted state; it never hides a row. Hide ordinary failed rows and finished-delivered rows. Preserve stage/repository/numeric-item/full-ID ordering and existing row fields. Print `Hidden historical jobs: N (use --all to show).` after rows only when N > 0. If the default view has only hidden history, first print `No active background jobs.`; if no directories and no diagnostics exist, retain exactly `No background jobs.`. Do not report an error-only inventory as empty. `--all` prints every row with the new wording and no hidden-history footer. Listing never compacts anything.

4. Extend `cli.py::main` and `_jobs` with `jobs --all` and `jobs compact`. `--all` is valid only for listing, not compact/stop/release or another command. Compact accepts no ID. Keep existing stop/release ID validation, options and exit codes. All jobs forms dispatch before configuration or credential loading. Invalid new combinations exit 2 before inventory or mutation. No JSON mode or force flag is added.

5. Add `specloop_job.compact_history(state_dir)` returning a structured report with per-attempt outcomes (`compacted` or `skipped`, full ID/context and reason), diagnostics and an operational-error indicator. Enumerate complete local inventory in existing order, without the CLI filter. Every recoverable attempt gets exactly one outcome. Read parent receipts without following symlinks; require `delivered is True` and `receipt["job"] == job.id`, and pass the unchanged receipt to `compact_delivered`. Never synthesize a job field, accept `round_job` alone, infer dates or use `resume_cleanup` to bypass a replaced receipt. Existing locking, under-lock rereading and keyed identity validation remain authoritative. Absent/mismatched receipts, pending/failed/stopped/live attempts and already-complete valid journals are skipped with reasons. A journal counts as already compacted only after existing identity checks succeed. Repeat the pass to resume an incomplete journal only while the current receipt still matches.

6. Explicit CLI invocation authorizes local cleanup of matching delivered evidence even while Nightshift is paused and without current GitHub labels or configuration. This is the narrow MODIFIED exception to automatic cleanup's eligible/authorized/unpaused-visit rule. It grants no launch, delivery, receipt mutation or replacement-journal recovery authority. Preserve the helper's signature/return contract for daemon callers; any internal reporting seam must keep their behavior unchanged. Update its caller-contract comment accordingly. No daemon code changes are needed.

7. `jobs compact` prints one contextual line per outcome and a final `Compacted: N; skipped: M.` summary. Empty state prints `Compacted: 0; skipped: 0.` without creating directories. Count an attempt as compacted only when this invocation completes previously incomplete cleanup, even if unsafe idea targets were retained with warnings; print those warnings explicitly. Already-complete attempts count as skipped. Expected ineligibility (including missing/replaced identity or a busy lifetime lock) is a successful skip. Malformed/unreadable evidence, unsafe evidence symlinks or filesystem failures produce diagnostics and exit 1, while independent healthy attempts continue; otherwise exit 0. Unsafe individual idea targets retained by the existing helper produce warnings, not false claims of deletion. A partial transaction is reported skipped with its error; its journal enables a later matching retry. Do not parse human diagnostic strings to infer successful mutation: use structured internal outcomes or validated journal state while preserving the public helper contract.

8. Tests use temporary trees and existing compaction fixtures, fake clocks, locks and injected filesystem failures; forbid configuration, network, subprocess and signaling calls for local commands. Add the four named tests from the issue. Cover receipt truth values and damage, mixed/default/full/empty inventory, all tracked stages and keyed revisions, changed receipts during locking, interruption/repeat behavior and reporting. Reuse existing recovery, ownership, touchpoint and authorization-denial suites. Only exact inventory-output assertions may migrate; retain all others. `uv run pytest` is implementation acceptance; also run `uv run python scripts/check_types.py` without growing the baseline.

9. Update only stale passages of the three scoped operator documents. Qualify automatic cleanup restrictions as daemon restrictions, add the explicit command and its limits, and point history inspection to `--all`. Preserve the artifact table and accurate recovery/retention limitations. Cite issue #103 until its implementing PR is known. No new prose-matching tests are needed; retain documentation checks. For heading boundaries, match exact column-zero heading lines, require a unique match, and stop at the next column-zero heading of equal or lesser depth. Missing/duplicate boundaries block the edit; do not interpret fences, HTML or indentation. An ambiguous heading-looking example blocks rather than silently choosing an occurrence.

## Risks / Trade-offs

Item-level delivery display cannot establish attempt-level deletion ownership. Pre-#9 receipts lacking exact job identity and older attempts behind a replacement receipt remain uncompacted. This can leave substantial storage; never reconstruct provenance just to clean a directory. Failed wrappers move to `--all`; malformed records stay visible. Listing snapshots can become stale immediately, so compaction rereads under existing locks.

The manual exception must not leak into automatic cleanup. Preserve authorization-denial and pause snapshots and daemon journal recovery rules. Reclaiming logs and inputs is irreversible; no directory deletion or secure-erasure claim is made. Pausing does not terminate detached jobs or the independent supervisor, so lock checks remain required.

Human checklist for the implementation PR (not implementing-agent tasks): pause the real daemon, capture `nightshift jobs --all` and relevant receipt/artifact snapshots on the real `~/.nightshift` tree, then run `nightshift jobs compact` once and capture `nightshift jobs --all` again. Compare stable IDs, execution/delivery classifications, counts, request mtimes, results, control records and skipped artifacts; verify only reported eligible logs/owned inputs and idea arguments changed. Inspect retained-target warnings and identity skips. Confirm the default view exposes pending, stopped and active work. Record commands, outcome and unexplained differences before resuming. A paused detached job may finish during inspection; account for that separately. CI proves synthetic filesystem behavior, not safety on this host's historical tree. Also check changed operator prose and live issue/PR references; keep unperformed checks pending.
