## Context

The checkout includes #16's worker retirement. `nightshift/cli.py` implements front-door commands; `specloop/cli.py` implements build commands. Their run/status/pause/resume verbs collide. The frozen wrappers execute `/opt/homebrew/bin/uv run nightshift run` and `/opt/homebrew/bin/uv run --no-sync specloop serve`. All `bin/**` and `launchd/**` files remain unchanged.

Build paths currently come from import-time `specloop.state.ROOT`, independent `agents.homes_dir()`, literal report defaults and `nightshift.deploy.Context.supervisor_state`. The daemon already owns `~/.nightshift`, including repository-keyed proposal receipts and their `<number>.jobs` evidence. `specloop/cli.py:propose()` currently selects `proposals/<change>` and `specloop/propose.py:draft()` recursively replaces it. Sharing that namespace after the root switch would let a valid change such as `owner__repo` delete daemon evidence during ordinary drafting, even after successful migration. Separate namespaces must prevent that collision throughout the lifecycle. Run locks use flock on a run-local inode; supervisor liveness currently uses heartbeat/PID checks without a serve lock.

`verify.profile()` currently adds built-in credential denials only during preparation. Real-path sandbox matching means directory denials miss external auth symlink targets. `Manifest` currently drops profiles unused by roles. Revision crash fixtures pin legacy paths in every child and must be migrated along with startup activation.

## Goals / Non-Goals

Provide one canonical CLI, safe resumable relocation, read-only fallback, and manifest-independent credential protection. Preserve state/event bytes, Git evidence, identities, control state, JSON schemas and unaffected assertions.

Do not edit wrappers/plists, trusted manifests, CI configuration, lockfiles or live state. Do not bulk-rename internal modules, configuration directories, refs or enrollment values. Keep docs paths such as `docs/specloop/` stable. This does not guarantee protection from detached old writers, whole-migration atomicity, automatic rollback or power-loss durability.

## Decisions

### Routing and compatibility

Expose a side-effect-free parser construction seam in `nightshift/cli.py`; reuse build parser/handlers in `specloop/cli.py` without recursive forwarding. Keep internal modules and the existing pyproject script targets/package list.

| Invocation | Dispatch |
| --- | --- |
| `nightshift run CHANGE` | Build driver |
| Bare `nightshift run`, including daemon --once/--config | Daemon run; sole implicit daemon compatibility exception |
| `nightshift daemon run` | Same daemon function as bare run |
| `nightshift status [CHANGE]`, or no arguments | Build status |
| `nightshift pause CHANGE`, `resume CHANGE` | Build controls; missing CHANGE is an argument error |
| `nightshift daemon status`, `pause`, `resume` | Existing daemon controls; daemon alone defaults to daemon status |
| admit/propose/revise/act/accept/waive/abort/publish/finish/drill/serve | Existing build syntax at top level |
| jobs/attention/preflight/reconcile/digest | Existing noncolliding front-door commands |
| `nightshift migrate` | Migration only; exits without scheduler work |

Daemon-only options on `run CHANGE` fail parsing. No other missing build operand dispatches to the daemon. Preserve daemon env-file loading, config-independent daemon pause/resume, offline jobs, help and exit codes. Keep the exact `--json` token before standalone `--` argument-error contract and one stdout JSON document. Read-only commands/help do not migrate or create state.

For one release `specloop` and `python -m specloop.cli` print the rename notice only to stderr and forward argv to the canonical dispatcher. Existing valid build invocations preserve results and status; no shell or extra process is needed for forwarding. Internal imports remain valid. Only landing status/finish calls in `nightshift/land.py` and driver children in `specloop/serve.py` switch to `[sys.executable, "-m", "nightshift.cli", ...]`, preserving interpreter provenance. Landing has explicit MODIFIED deltas; no existing requirement prescribes supervisor child module spelling. Alias removal and wrapper modernization are follow-ups.

Keep daemon-side command argv unchanged in `nightshift/specloop_client.py`, `specloop_intake.py`, `specloop_job.py`, `specloop_attention.py` and deploy's status reads. This preserves issue-intake's Drafting from an issue, Approval admits, Publication and File based drafting input; pr-revision's Spec-stage revision and Build-stage revision; attention's Stale tolerance; deployment-drift's Process age drift; and every specloop-interface requirement. Do not add broad deltas restating those requirements. Their caller migration and necessary MODIFIED deltas belong to alias removal. Deploy still gains resolver-backed state paths in task 2.11 without changing its `uv run --no-sync specloop status --json` argv.

The unchanged specloop-interface machine contracts govern both CLI names. Reuse existing isolated contract fixtures to compare canonical and alias stdout documents/exit codes. Task 1.3 adds a runner-adapter regression that captures the real alias entry point's stdout/stderr separately and passes its result through the unchanged daemon client, including a structured nonzero outcome. Exercise attention and deploy status parsing with the notice on stderr and retain intake/background request-identity assertions. A notice must neither pollute JSON nor turn valid output into an error; existing invalid-output and stale/error guards remain. The revision crash fixture keeps its `specloop` boundary assertion and candidate `specloop.cli` execution, whose forwarding reaches the canonical dispatcher; retain provenance and PATH-sentinel checks while migrating its state paths in tasks 2.1/2.8.

Task 1.2 migrates canonical behavior tests at the forwarding boundary, including `tests/test_specloop_status_json.py` and `tests/test_specloop_argparse_json.py`: call `nightshift.cli.main`, retain implementation-helper imports and patch the owning modules for handler and credential guards. Keep exact JSON, empty canonical stderr, exit codes, explicit/process argv, option termination and propagated exceptions; help/usage names become nightshift. Only empty human argv changes from an error to default build status. A lone --json and unsupported global --json syntax still fail without dispatch. Separate alias tests require exactly one stderr notice per invocation, including help and errors, while retaining canonical stdout and exit status. Do not relax canonical assertions to accommodate alias notices or route all tests through the alias.

### Lazy state interfaces and isolation

Add `state_root()`, `legacy_root()`, `runs_dir()`, `run_dir(change)`, `iter_run_dirs()`, `proposals_dir()`, `homes_dir()` and heartbeat lookup in `specloop/state.py`. Trusted absolute `NIGHTSHIFT_STATE_ROOT` and `NIGHTSHIFT_LEGACY_STATE_ROOT` propagate roots to subprocesses; reject blank/relative overrides. These settings never come from RPC or candidate inputs. `agents.homes_dir()` delegates to the resolver.

Named reads prefer existing canonical state, then legacy state, then the canonical path for a new run. Discovery yields a name-sorted union once per change, deduplicates migration links and retains per-run errors. Distinct unjournaled duplicates block writes/migration and produce read diagnostics rather than hiding evidence. Reads never create directories, repair journals or load credentials. Existing legacy run writes use their resolved directory/lock; new entries use canonical paths. Draft replacement follows the separate namespace rules below.

In `tests/test_specloop_serve.py`, use isolated roots containing a legacy-only run and a canonical run with a legacy compatibility link; assert both are returned exactly once without discovery writes. Add an autouse temporary HOME and both root overrides in `tests/conftest.py`, coordinated with existing daemon/outcome/heartbeat/pause fixtures and local state.ROOT patches. Patch relevant import-time daemon constants to this temporary tree. Children explicitly inherit or replace these temporary settings. A guard intercepts filesystem operations against the actual home's lexical/canonical state paths and fails before access; child probes verify inherited isolation. Capturing forbidden path names must not read their directories. No test reads or copies live state.

Migrate `tests/test_daemon_retirement.py:207,411–412` onto lazy resolver/temporary-home assertions. Preserve the exact wrapper argv/bootstrap/credential assertions at :416/:429 and `tests/test_host_portability_docs.py:140–146`.

### Exclusion

Add `specloop/state_locks.py`. Keep a stable coordination lock at `<legacy_root>/.migration.lock`: upgraded writers acquire shared ownership before resolving paths and retain it throughout the operation, including proposal and agent-home users. Migration acquires exclusive ownership nonblocking. Pending incomplete journals block ordinary writers with the recovery command; only migration recovers them. Reads remain read-only.

Serve holds `<legacy_root>/serve.lock` exclusively for its entire lifetime, including --once. Migration obtains serve lock, then coordination lock, then all legacy and journaled destination run locks sorted by change; retain them through relocation. Never rename/unlink the global lock files. A second supervisor/migrate refuses clearly instead of waiting indefinitely. Check both root heartbeats for old supervisors lacking the new lock: a live PID, permission-denied probe or malformed/uncertain heartbeat blocks migration conservatively. Known-dead heartbeat evidence is retained until normal startup replaces its heartbeat.

Before any entry moves, acquire every existing real legacy run's lock inode nonblocking. A held lock refuses the entire migration with the change name and pause/stop/retry guidance; no legacy runs/proposals/homes or canonical runs/drafts/proposals/homes entry changes and no completion marker appears. Creating stable coordination lock files is permitted during refusal; entry journal intent is written only after preflight succeeds. New supervisor heartbeat is canonical serve.json, separate from daemon heartbeat.json; readers/deploy use canonical-first legacy fallback. Global lock order, including serve startup's reuse of its owned serve lock, must avoid self-deadlock.

### Relocation and process recovery

Add `specloop/migrate.py`. Migration returns 0 for complete/no-op and 1 for refusal/incomplete recovery; errors identify affected paths without credential contents. There is no force flag, network use, configuration requirement or scheduler call.

Use `<canonical_root>/.specloop-migration-v1.json` as an atomic journal and `<legacy_root>/.migrated-to-nightshift-v1.json` as completion marker. Journal version, root identities, separate source-relative and destination-relative entry paths, device/inode identities, original symlink destinations and phases. In particular, record `proposals/<change>` to `drafts/<change>` explicitly; recovery must not assume equal relative paths. Write the completion marker only after every entry and compatibility link completes. A valid marker makes later calls no-ops without rescanning/moving late legacy artifacts. Malformed/mismatched markers refuse. Empty legacy state completes once; interrupted attempts resume the existing journal.

Preflight every immediate legacy child of runs/, proposals/ and homes/ against the fixed destination mapping above. Legacy proposals target drafts/, never canonical proposals/. An existing daemon receipt directory with the same name is unrelated evidence and neither blocks migration nor becomes a migration destination. A distinct existing drafts/<change> is a true collision and refuses. Never replace these parent directories or overwrite existing canonical daemon receipts, outcomes, claims, jobs, admissions, revisions or pause. Accept existing destinations only when journal identity proves the same moved entry or a completed legacy link points there. Otherwise refuse without content-based guessing. Refuse unsupported top-level symlinks, traversal, overlapping roots, unreadable evidence and cross-device relocation before moving anything. No copy/delete fallback.

For each entry: persist intent and symlink plan, rewrite relative symlinks whose targets escape that entry to absolute original destinations, atomically rename on the same filesystem, then create an absolute compatibility symlink at the old path. Internal relative links remain relative. Determine external destinations from original parents, including dangling targets; never copy credential bytes. Compatibility links preserve immutable manifest/receipt/log paths and worktree metadata; do not recursively rewrite historical text. Renaming run directories preserves lock inodes. Keep legacy parents and per-entry links for the fallback release.

Each rewrite, rename, link and marker step has an idempotent phase/identity check. Fresh-process recovery recognizes source-only, moved-but-unlinked and linked-but-unmarked states. Refuse both-missing, conflicting or corrupt evidence without deleting either side. A partly rewritten source stays readable; writers wait for recovery. Test process exits around each transition, without claiming power-loss durability.

### Activation and crash fixtures

Land resolver, exclusion, relocation and recovery before activation. Automatic migration runs only at serve startup, before polling/spawning, reusing the held serve lock. Other commands use resolver fallback without implicitly migrating. Startup migration is a fallback, not the rollout procedure.

`nightshift migrate` refuses while a live supervisor holds the serve lock, including alias-launched serve. Runs paused for infra or usage_limit with due deadlines stay byte-for-byte paused; migration appends no auto-resume event and spawns no driver. Never prescribe serve --once for migration.

## Risks / Trade-offs

Compatibility links preserve absolute historical references but retain legacy paths for one release. Separating drafts from daemon proposals avoids collisions from arbitrary valid change names; existing canonical draft collisions still demand refusal, and cross-device layouts need separate operator planning. Re-drafting an unmigrated legacy workspace requires migration first instead of silently creating competing copies. Upgraded locks cannot prove detached old writers are absent; the quiet window remains necessary. Process-crash fixtures cannot prove machine/power-loss durability.

Eighteen tasks are intentional: draft namespace isolation, locking, relocation, recovery, activation and subprocess fixtures have distinct safety boundaries, each targeted at roughly 300 changed lines or less including tests. Boundaries are fixed before admission since implementers cannot edit openspec. Internal package moves are avoided.

Nested harness sandboxing can skip OS probes; unsandboxed macOS CI must execute them. Neither CI nor synthetic fixtures prove live service setup or migration safety.
