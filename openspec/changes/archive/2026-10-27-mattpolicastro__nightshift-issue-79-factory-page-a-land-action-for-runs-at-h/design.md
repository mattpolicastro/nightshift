## Context

Factory uses `plugins/nightshift/server/factory.ts`, `shared/factory.ts` and `client/factory.tsx`. Ordinary reads share a 15-second cache; refreshes occur on mount, at the existing active 60-second interval, on foreground return and manually. Actions use `nightshift act`. Results follow the originating visible row or appear above the list when absent/folded. Existing labels, styles, behaviors and assertions are protected.

Status supplies `head`, `pause.reason`, `action.pause_id` and `pause.since`. Publication can repeatedly emit `human_checks:` after revision, so pause_id alone is insufficient. Since is the last recognizable pause event's epoch seconds, including zero and fractions. Preserve the ordinary Factory pause projection's two fields (`since`, `auto_resumes_remaining`); use a separate landing offer.

`nightshift.land.main` accepts an injectable runner but no expected-head CLI flag. It owns the final `--match-head-commit` merge and validated head evolution through finish/base update. Its attestation selector refuses duplicate markers when a lookup occurs; a valid POST acknowledgement returns without another lookup. Thus a delayed earlier POST can create duplicates without making that invocation refuse. The existing dependency checker follows imports and module targets through the canonical CLI. No applicable AGENTS.md was found in this checkout or its ancestors.

## Goals / Non-Goals

One deliberate confirmation starts a detached, inspectable attempt for the displayed pause. Use one small worker module, one per-PR lifetime lock, bounded display records and existing landing gates.

Do not add durable request replay, intake holds, release adapters, an uncertain outcome state, descendant lock inheritance or a foreground supervisor. Keep proof of prior execution-group termination. Attestation behavior is exactly terminal land's: no durable create intent, unresolved-key evidence or cross-attempt POST guard. Do not schedule landing from daemon/serve/job-control/CLI paths. If finish succeeds before a later landing refusal, retain the reason but offer no Land for done: the existing standalone landing command provides recovery after process and remote-effect inspection.

## Decisions

### 1. Private transport and execution boundary

Add `nightshift/factory_land.py` with private `start`, `status`, `stop`, `worker` and `invoke` modes. These are plugin plumbing, not canonical CLI subcommands. Do not edit `nightshift/specloop_job.py`, register forwarding in either CLI, or add imports/dispatch from daemon, serve, intake or job control. Keep the dependency checker and all existing landing assertions. Update only exact finish-argv expectations/helpers to include the new head argument; do not weaken or remove assertions. New boundary tests reuse traversal from daemon, supervisor, both CLIs and job control, assert the new module is unreachable, and use launch spies on read/control paths. No lazy/computed imports or checker exclusions conceal dependencies.

The plugin calls configured uv with literal `['run', '--no-sync', 'python', '-m', 'nightshift.factory_land', ...]`, configured checkout and existing Factory PATH. The short start transport persists admission then launches the same module's `worker ATTEMPT_ID` with that configured uv prefix using `Popen(start_new_session=True)`. It returns the attempt ID immediately after spawn, without waiting for landing or supervising it. Trusted host settings alone select executable/cwd/PATH; reuse host-path resolvers and test spaces in paths.

The worker acquires the lock itself, verifies prior groups have drained and durably records its actual Python PID, start time, session and group (uv may be group leader) before launching any invocation child. It launches `[sys.executable, '-m', 'nightshift.factory_land', 'invoke', ATTEMPT_ID]`, which calls `land.main([pr, '--checks-done'], runner=confirmed_runner)` with its existing attestation logic. Land and its finish subprocess stay in this same new session/group, without another setsid. The worker waits for its child while holding the lock; there is no additional foreground supervisor or descriptor handoff. Failure to persist execution identity refuses before child creation.

Only a human-confirmed Factory submission reaches start. Reading status, mounting the page or polling the daemon cannot launch work. Explicit terminal use of land receives the same narrow finish head guard, including the partial-finish recovery migration below; all other executable behavior remains unchanged. This is an application dependency boundary, not OS authentication against trusted local operators executing Python modules.

### 2. Frozen offer and handoff

Offer identity is `{change, pr, pause_id, head, since}`. Require a safe existing change identifier, canonical GitHub HTTPS PR URL without credentials/query/fragment, full 40-hex head, valid pause_id and finite non-boolean since. Preserve zero/fractions without rounding. Produce offers only from successful version-1 status showing paused human_checks with complete metadata. Missing/legacy/error metadata yields no offer and a diagnostic without failing ordinary run reads.

Syntactically valid admission refusals receive their own attempt ID and retained reason without a worker; malformed input creates no evidence. Private start argv is `start CHANGE --pr URL --pause-id ID --head SHA --since SECONDS --checks-done --json`. The server checks the last good displayed offer and known ordinary run; Python admission rereads status and remote PR head and compares every field. After taking the lock, worker startup independently repeats this validation before invoking land. A daemon pause file blocks admission/startup; it does not kill running landing. Status and Stop remain usable while paused. A failed identity read never grants permission.

Supply the confirmed identity to the child's runner. Check the actual initial PR/status responses consumed by land, and fresh pause/head identity before pre-finish mutations, so a revision between preflight and land discovery cannot silently authorize a new pause. Match existing command shapes, refuse an unknown pre-finish mutation, and forward genuine responses unchanged. Do not parse checklist Markdown or duplicate enrollment, check selection, attestation, CI or merge gates. After the finish call, land owns validating the done/finished-head transition and base-update provenance; its final match-head-commit names the verified successor, not forcibly the pre-finish SHA.

There is no client request UUID, replay index or replay-before-eligibility path. Each explicit confirmation creates a fresh attempt ID. A concurrent contender records a lock refusal; a later attempt uses fresh identity, prior-attempt guards and unchanged land eligibility/head checks. The page recovers a lost response by status, never automatic resubmission. A new deliberate confirmation is required to try again.

Close the remaining check-to-finish race at the existing run lock. In `specloop/cli.py`, add optional `--expect-head SHA` to the shared finish parser, accepting a full 40-hex SHA (normalize case); malformed values exit 2 before dispatch. In `_finish`, after `_locked_command` has acquired the lock and reloaded state, compare `ctx.head()` to the supplied SHA before task inspection, archive creation, commits, pushes or marking the PR ready. A mismatch or failed head read returns nonzero with expected/observed identity or the read failure, leaving run state and the archive untouched. Without the option, preserve existing finish/act behavior; use an optional lookup for act's namespace. Existing human_checks, completed-task and repository gates still apply.

The sole edit to `nightshift/land.py` appends `--expect-head` and `refreshed_pr.head` to `finish_run`'s current-interpreter finish argv on every invocation that calls finish, including terminal use. The validated PR head is the pre-finish identity; do not use a later discovery to replace it. Keep the 300-second limit, same-run done check and successor-head handling at the existing finish boundary unchanged. Direct PRs and initially done runs continue to skip finish. An adapter check immediately before dispatch is useful but cannot replace the locked guard: a revision can republish after that check and before finish acquires the lock.

This deliberately changes partial-finish recovery for terminal and Factory callers. Finish can create archive commit A on the local run branch, then fail pushing it while GitHub still reports H and the run remains paused at human_checks. A new terminal land invocation must still pass H; locked finish refuses local A before further finish effects. Factory may refuse even earlier because the local offer head A differs from remote H. Neither path may substitute A, skip the guard or infer that A is a safe archive successor. After all attempts have stopped, the operator inspects A, its archive/tasks, the remote H and the failed push, then explicitly uses direct Finish (the existing Factory Finish or terminal finish/act without --expect-head). Existing recovery reuses A, pushes it and marks the run done without a second archive commit. The operator then reviews the remote head and reruns terminal land; done-run continuation skips finish and repeats all landing gates. If the push already succeeded and only ready/state completion failed, matching local/remote heads still permit guarded recovery. No run reset or automatic unguarded fallback is added.

Factory delegates attestation completely to land, just as terminal invocation does. Its existing paginated selector, POST acknowledgement and within-invocation reconciliation are the entire attestation story. A late-committing POST can leave duplicate markers across invocations. A valid acknowledgement does not guarantee a fresh duplicate lookup; a subsequent lookup refuses `duplicate marker matches; resolve duplicates before retrying`. Inspect effects, delete one duplicate comment, then deliberately retry if eligible. Do not retain create intent or introduce a guard that can permanently block a PR when a POST was never sent. The MODIFIED `reviewed-pr-landing/Stable check attestation` delta explicitly replaces the former unqualified one-comment / before-any-retry guarantee with invocation-scoped reconciliation. Each invocation looks up the marker before creation, sends at most one POST, reconciles an ambiguous response and refuses that invocation if reconciliation fails. A fresh explicit invocation may POST when its own lookup sees none, even after an earlier ambiguous create. This accepts possible cross-invocation duplicates; it does not change land.py attestation code or relax head, finish, CI or merge gates. Process-group absence proves local drainage only, never completion of a request already accepted by GitHub.

### 3. Records, lock and Stop

Use the existing Nightshift state root at `landings/<owner__repo>/<pr>/`, containing a stable `lock` file and `attempts/<attempt-id>/`. IDs are generated by the start transport as evidence identifiers, not idempotency keys. Persist `request.json` before spawn; worker writes `process.json`, bounded `progress.json`, complete `output.log` and small atomic `result.json`. Keep confirmed identity, timestamps, phase, exit status, outcome and reason. Known spawn failures become retained failures. No intake receipt or RunState mutation is introduced.

Take nonblocking exclusive flock on a case-normalized repository/PR lock file before landing and hold it for the worker's lifetime. Contention yields a retained refusal without invoking land. Never unlink the lock file or use pass_fds. Descendants do not inherit the descriptor. Worker exit/crash releases the lock, but lock availability alone is not permission to mutate.

Under that lock, inspect every earlier recorded group not already proven drained, independently of terminal outcome and the newest-20 display bound. Validate each recorded group is a safe positive ID greater than one, outside the caller/current worker group, then use `os.killpg(pgid, 0)` solely as a kernel existence probe: only `ESRCH` proves absence. Success, permission denial or any other error refuses new invocation; no signal is delivered by this probe. Even an unreaped zombie group conservatively blocks until absent. A missing worker and unchanged five-field offer never override a surviving group. PID/group reuse can conservatively block but never authorizes signalling. Persist a small drained observation only after confirmed absence under the lock; status reads never do so. Do not infer drainage from a process-list snapshot, elapsed time, a result file, missing worker PID or released flock.

Every invocation and mutating subprocess remains in its recorded group; neither the adapter nor its launch calls creates another session after worker launch. An absent group cannot acquire a child from its former members. Missing process metadata means invocation was never permitted to start; corrupt metadata fails closed. Publish process metadata by syncing a temporary file, atomic rename and directory sync before child spawn, and test death on both sides of that boundary. Retain undrained process evidence regardless of displayed outcome; manual log pruning must not delete those records.

A missing worker without a result produces an interrupted-failure diagnostic, never success or an uncertain hold. No automatic relaunch or read-side repair occurs. A starting record without process metadata stays visibly starting for a 60-second launch allowance, then reports startup not established. A delayed worker still takes the lock and validates fresh identity before acting.

Private `stop ATTEMPT_ID --json` verifies recorded worker PID plus start time and current group membership, rejecting unsafe/caller groups and unverifiable identities, then sends SIGTERM to that group. Return stop requested, not unproved stopped. Normal worker signal shutdown records stopped and releases its lock; missing terminal records remain diagnostic. Preserve already terminal outcomes. A TERM-resistant tree remains running with a diagnostic for inspection. No SIGKILL escalation, persistent cancellation hold or jobs stop/release adapter is added.

If worker identity is gone, Stop explicitly refuses even if descendants survive. Recovery is to wait for them to finish or kill them by hand; a subsequent confirmed attempt must independently prove the old group drained before invoking land. No orphan signal, inherited descriptor, escalation adapter or supervisor is introduced. Stop cannot roll back remote effects. An interrupted attempt is a retained failure with a specific blocking reason, not a new uncertain outcome state.

### 4. Bounded history and progress

Private `status [CHANGE] --limit N --json` accepts 1–20, default 20. Return version 1, newest-first attempts, total before slicing, diagnostics and, for named queries, the offer and current live attempt separately. Locate current progress using small process metadata independently of history order; refused contenders cannot hide the running worker. Global reads restore recent results for removed runs; named reads restore current progress for visible/locally tracked changes outside that page.

Enumerate small metadata to count/select, then read only selected bounded summaries and current progress. Never read full logs or unbounded historical result bodies for display. Cap each detail at 8192 Unicode characters and bound other fields; truncate explicitly to serialize below 1 MiB UTF-8, under the 2 MiB subprocess cap, preserving current identity/progress. Full output stays in the log. Damaged records produce diagnostics alongside healthy entries. Reads never launch, signal, deliver, compact, repair or acknowledge results.

Report phases from existing runner calls (validating, recording checks, finishing, checking CI, merging) without percentage claims. Persist timing with a 2400-second display-only overdue threshold; land retains its own command bounds and 1800-second CI budget. Success requires land's confirmed merge, not successful spawn. Complete evidence remains until manual pruning; undrained-group records must be retained. Bounded output does not bound storage or metadata enumeration cost; safety scans use all relevant small records, never the display slice.

## Risks / Trade-offs

- Seven single-concern sessions target roughly 300 changed lines each including tests. Removing durable attestation reconciliation leaves six; the approved split of the former worker task separates the locked finish handoff from process lifecycle, yielding seven. Reuse fixtures; these are guidance, not caps that justify dropping assertions.
- Worker-only death releases flock while descendants may survive. Kernel group-existence probes block another invocation until absence is proved, even with unchanged identity. Stop refuses without worker identity; wait or manually terminate descendants. Unverifiable/reused group IDs and unreaped zombie groups conservatively reduce availability.
- A delayed POST can create duplicate markers across invocations, as with terminal land. A later lookup refuses until one duplicate comment is deleted. This accepted availability/recovery exception adds no cross-attempt guard and cannot authorize merging an unvalidated head; other landing gates remain authoritative.
- The head guard intentionally prevents landing from recovering a locally archived but unpushed run by itself. Inspected direct Finish remains available without the flag; this operator step trades convenience for refusing unrelated local heads under the run lock.
- SIGTERM is not rollback or guaranteed termination of resistant/escaped descendants. Independent terminal land invocations do not take the Factory lock.
- Evidence grows until manually pruned. Bounded summaries protect display output; metadata enumeration can still slow with history.
- The confirmed runner depends on current land command shapes; tests exercise the actual entry point and final verified successor head, changing land.py only to pass the validated head into finish.
