## Decisions

1. **Keep landing operations and policy local to land.** Introduce a small internal `LandingForge` operation interface in `nightshift/land.py`, with GitHub and Gitea implementations there. Named operations cover PR/main reads, comments/actor reads, source/attestation writes, exact commit facts, ancestry, update, checks, merge and confirmation. Keep lifecycle, trust, marker selection, deadlines and provenance in the existing landing functions. GitHub operations use `Operations.run/read_json` and the existing injected runner with exactly the same argv, order, field strings, timeouts and body bytes. Preserve existing helper defaults and `main(..., runner=..., sleep=..., monotonic=...)`; add keyword-only opener/operation injection for Gitea tests. Do not translate arbitrary gh argv into HTTP or add a generic command escape hatch to the shared Forge protocol.

2. **Select by URL, then constrain the destination.** Load `--config` before selection. Preserve implicit GitHub.com and explicitly GitHub-kind enrollment, GitHub bare numbers, `--repo` and `gh repo view` exactly. Gitea requires a full URL: match its case-insensitive hostname to exactly one configured Gitea definition; zero or multiple matches refuse, even if a port could disambiguate. Next require configured scheme, effective port and path prefix plus `/owner/repo/pulls/<positive-number>`. Reject userinfo, query/fragment, whitespace/control/backslash, traversal, malformed escaping and contradictory `--repo`. Permit HTTP only at a configured loopback origin, as the existing transport does. Match enrollment case-insensitively but use its configured owner/repository spelling for Gitea API paths and canonical identity; do not inherit GitHub's unconditional lowercasing. Require that enrollment selects this same forge. A Gitea row never authorizes GitHub landing. Build all `/api/v1/...` paths from validated components at the configured root, never from a response URL. Verify returned PR number, canonical URL, full head SHA, open state and `base.ref == main`. Draft means the configured case-sensitive WIP title prefix. Discover runs by full canonical PR identity, including origin/prefix; a well-formed other-host row remains unrelated, while a malformed target-host URL blocks discovery.

3. **Load only human landing credentials for Gitea requests.** In land, parse `Path.home() / '.config/nightshift/land.env'` with `config.parse_env_file`, without a shell. The existing physical-line format is `export NAME=VALUE`, with matching outer quotes removed and no expansion or command execution. Overlay file values on an invocation-local copy of the environment; file presence wins even for an empty selected value. Missing file permits an already supplied selected `land_token_env`; unreadable files and absent/empty selected values refuse before HTTP. Do not load the bot env file, consult `token_env`, use ambient gh auth for Gitea or mutate `os.environ`. Never pass a loaded human token to status/finish argv or environment. The existing #129 finish subprocess retains its separately provisioned bot/git credentials and forge config; document aligning `NIGHTSHIFT_FORGE_CONFIG` with a custom landing `--config` without changing finish argv. GitHub retains existing operator gh authentication. Errors identify stage/variable without values or remote bodies. `/api/v1/user` identifies the attesting actor; with listed checks and `--checks-done`, require a non-bot actor in `trusted_logins` before edits so the created attestation will be trusted on retry.

4. **Reuse factual reads, retain landing-specific trust and writes.** Construct GiteaForge with the human token for `comment_pages`, `commit` and `checks_for_sha`; use GiteaTransport for landing-specific raw PR/main/user reads and writes. A local opener wrapper caps each dispatch timeout by the remaining `Operations` budget and checks the budget before and after dispatch; supply a guard so GET retries/pages cannot dispatch after expiry. Bind each logical call to the current Operations budget, including its bounded replacement after finish, rather than capturing the initial unbounded object. Transport backoff and read time consume the original deadline; no outer retry or new grace period is added. Fake clocks verify expiry across retries as well as polls. Both transports receive the same confined origin and human credential.

   Ignore projected `author_association` when deciding Gitea landing trust; use casefolded `comment.user.login` membership in selected `trusted_logins`. This intentionally permits a listed publication bot, unlike feedback intake. An unlisted owner or administrator is untrusted. Do not reuse GiteaForge's bot-owned `create_comment`/`update_comment` methods for human attestation or publication checklist edits. Use a single direct PATCH/POST through the landing operation after the existing trusted-source gates. Preserve complete comment pagination and malformed/conflicting-page refusals.

   Retain the exact physical checklist rule `^[ \t>]*[-*+] \[( |x|X)\] ` on every line; fences, headings, HTML and indentation never hide a matching line. Tick only the matched state character. Publication selection retains literal `**nightshift** —` at body start and the existing literal `<!-- nightshift:publish:<change>[:<round>] -->` token search, newest `(created_at, id)` ordering, and validation of selected IDs/timestamps. Attestation retains exact substring lookup for `<!-- nightshift:land-checks:<pr>:<head> -->` across all comments, including examples. 5. **Prove a base merge after one update attempt.** Read main via `GET /api/v1/repos/{o}/{r}/branches/main` and validate its name and `commit.id`. For the initial Gitea ancestry check, traverse exact-SHA parents via `GiteaForge.commit`, with a visited set, until the captured base is reached or complete ancestry is exhausted. Equality proves inclusion without a request. Exhaustion means stale; malformed/unreadable facts or deadline expiry refuse, not permission to update. This uses known commit facts without assuming GitHub compare fields exist in Gitea; each SHA is read at most once per ancestry traversal.

   Before each necessary update, re-read the open, non-WIP PR and require head H to equal the expected head, then read main B immediately before dispatch. Send exactly one `POST /api/v1/repos/{o}/{r}/pulls/{n}/update` with query `style=merge`, no rebase and no fabricated expected-head request field. There is no server-side head CAS on this endpoint. A definite HTTP rejection refuses immediately. Connection loss, a transient server outcome or undecodable 2xx may be uncertain; reconcile through read-only observation, never a second POST. Poll within the shared deadline, accepting only the first changed head C whose returned commit SHA is C and ordered parents are exactly `[H, B]`. Reversed, missing, extra or other-base parents, descendants, closed/WIP PRs and failed reads refuse. Even a successful update acknowledgement must pass provenance. Retain B as the round baseline and require fresh CI for C. A later independently required base-update round may send its own single POST; an uncertain attempt is never replayed.

A closed PR alone or a queued/open result is not confirmation. Do not replay merge. Preserve the separate ordinary bounded timeouts for merge and confirmation after the CI budget ends.

## Risks / Trade-offs

- Gitea update has a read-to-write race. Exact parent validation detects an unexpected result after the write; it cannot prevent that remote mutation or roll it back. A competing push or base move causes refusal, even if its resulting history would otherwise be mergeable.
- Main may move after the final base read and before merge on either forge. Head conditioning does not lock main; server protection remains authoritative. A human may need to inspect an already accepted write after interruption.
- Walking ancestry is more expensive than GitHub compare, particularly on old branches. The shared deadline bounds it and fails closed. No new compare-response assumption or local-checkout requirement is introduced.
- Landing trusts only configured login membership on Gitea; operators must list both the human attester and any intended publication author. Empty trust does not authorize an owner. Human credentials are never a fallback for #129 finish, which still requires its own provisioning.
- Existing source read/modify/write and cross-invocation late-attestation races remain. Local Factory locking does not serialize terminal operators or establish completion of an accepted remote request.
- The narrowly shared `KNOWN-LIMITATIONS.md` edit can conflict with #151; re-read and reconcile only the command-boundaries bullet, preserving loopback and all other concurrent changes. Root/engine guides and the plugin remain outside scope. The landing guide must clearly distinguish terminal Gitea support from unchanged Factory UI eligibility and disabled daemon Gitea dispatch.

Human validation for the pull request (not implementation tasks):

- [ ] A human reviews and lands the first real Gitea PR with `land`, using the configured human token from `land.env`, and verifies the attestation actor and pre-finish head where checks are listed.
- [ ] Inspect an actual merge-style branch update when needed: the accepted head has exactly the reviewed head and recorded main as its ordered parents, and CI belongs to that new SHA.
- [ ] Inspect the resulting merge commit and Gitea PR's merged state, including real token permissions and protection behavior; record the observed PR URL and merge SHA without secrets. CI fixtures cannot prove a real Gitea merge.
