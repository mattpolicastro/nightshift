## Context

`nightshift/land.py` now contains #130's `LandingForge`, `GitHubLandingForge` and `GiteaLandingForge`. `continue_landing` records `main`, validates any update, calls `wait_for_ci`, revalidates inputs and compares the base before `after_ci` requests and confirms a head-conditioned merge. `ci_is_green` requires at least one pass. GitHub's narrowly recognized missing-check response and Gitea's proven empty combined status both normalize to pending registration.

The repository's `.github/workflows/ci.yml` ignores `**.md` for both push and pull_request. `CI_POLL_INTERVAL` is 10 seconds. Contrary to the issue's shorthand, there is no independent existing registration grace: #89 deliberately retained only the shared deadline. This design makes the docs-only grace explicit without extending that deadline.

`record_attestation` currently runs before finish and records human assertions only with listed checks and `--checks-done`. Its head can differ from the finished or updated head. A CI decision therefore needs distinct evidence, not an overwritten human assertion. Existing offline tests use strict runner transcripts, injected clocks and Gitea openers. No applicable `AGENTS.md` was found in this checkout or its ancestor directories.

## Goals / Non-Goals

Allow the reported Markdown-only case to land after a short registration opportunity, with evidence from trusted base content and an auditable reason. Keep uncertain file/workflow evidence on the ordinary CI path. Apply the policy to GitHub and configured Gitea without leaking credentials or changing their merge protocols.

Do not infer exemption from extensions alone, a PR label/body, a local working tree, or workflow content on the PR head. Do not implement general YAML, workflow execution, required-check configuration, multiple-workflow selection, or a force option. Do not change finish, source selection, human checklist semantics, Factory eligibility or background execution.

Only implementation paths `nightshift/land.py`, `docs/landing.md`, new `tests/test_land_ci_exclusion.py` and `tests/test_land_docs_only.py`, and narrowly extended existing landing test setup are planned. Existing assertions must remain. Do not edit `KNOWN-LIMITATIONS.md`, `docs/arming.md`, `docs/specloop/README.md`, `nightshift/arm.py`, `specloop/cli.py`, `tests/fake_gitea.py`, `tests/test_arm_forge.py`, `tests/test_arm_forge_docs.py`, `tests/test_arm_gitea_context.py`, or `tests/test_status_json_forge_link.py`. No runtime dependency or workflow file changes are needed.

## Decisions

1. **Factual reads stay in the landing boundary.** Add named `LandingForge` operations `changed_paths(identity, operations)` and `ci_workflow(identity, base_sha, operations)` in `nightshift/land.py`. Return validated paths (including old and new names for renames) and an optional workflow path/text; policy helpers decide eligibility. GitHub uses explicit-repository `gh api` reads of PR metadata/files and Contents at `ref=<full base SHA>` through `Operations`. Gitea uses confined `/api/v1/repos/{repo}/pulls/{number}`, its paginated `/files` endpoint, and Contents reads with the same pinned ref through `_transport(operations)` and the human token. Encode path/query components; never follow a response's download URL. Consume complete file pages, check the count against a nonnegative integer `changed_files` from PR metadata, reject duplicate/malformed entries and conservatively decline at a provider cap. Missing totals or unverifiable completion cannot prove exclusion. Require a nonempty changed-file list. Deletions count; a rename from code to Markdown still includes the old code path.

2. **Bound the supported workflow configuration.** Enumerate the selected forge's workflow directory at the captured base SHA: `.github/workflows` on GitHub, `.gitea/workflows` on Gitea. Eligibility requires exactly one regular `.yml`/`.yaml` workflow, named `ci.yml` or `ci.yaml`. Missing directories/files, additional workflows, symlinks, truncated responses, unavailable content, unsupported encodings or ambiguous metadata decline the exemption. Do not fall back from a missing Gitea directory to GitHub or Forgejo. This deliberately conservative single-workflow default covers this repository and avoids treating one workflow's exclusion as proof about other workflows.

3. **Use a small physical-line recognizer, not a general YAML parser.** Add pure `ignored_paths(workflow_text)` and `all_paths_ignored(paths, patterns)` helpers. Recognize exactly one column-zero `on:` (also allow single- or double-quoted `on`); its block ends at the next nonblank, noncomment column-zero line. Within it permit only two-space event headings `pull_request:` and optional `push:`, each once. Both declared events must have a supported ignore list matching every changed path. Event fields use exactly four spaces and are limited to `paths-ignore` and optional `branches`/`branches-ignore`; no repeated fields. Lists are either a single-line bracketed comma-separated list of quoted strings, or an empty field header followed by six-space `- 'value'`/`- "value"` physical lines. For branch lists only, also accept unquoted scalars matching `[A-Za-z0-9_./*-]+`, so the repository's `branches: [main]` is supported; ignore patterns remain quoted. Accept blank lines and whole-line comments. Require nonempty ignore lists and `pull_request`. Reject all other lines in this block, inline comments, escapes, anchors, aliases, merge keys, tags, flow mappings, multiline scalars, duplicate top-level on declarations and tabs in the trigger block. Do not search for an apparent nested `paths-ignore` elsewhere. Unsupported or ambiguous syntax means CI remains required, never an empty pattern list that matches everything. No new YAML dependency is introduced.

4. **Match a documented safe glob subset.** Match whole, case-sensitive repository-relative POSIX paths. Support literal characters, `*` (zero or more non-slash characters), `**` (zero or more characters including slash), and `**/` (zero or more directory components). Thus `**.md` matches root and nested Markdown, while `*.md` matches only root files. Reject negation, `?`, character classes, braces, backslash escapes and other unsupported pattern operators rather than approximating their meaning. Patterns cannot be empty, absolute or traversal paths. Do not normalize away meaningful path characters or match a basename in place of the full path. Every path must match at least one ignore pattern for each declared event. Any unknown evidence makes this proof unavailable, not green.

5. **Evaluate lazily before waiting, then pin proof to the round.** Extend `wait_for_ci` with optional `base_sha` and a result distinguishing ordinary green from a `CIExclusion` containing head, base, workflow and matched paths/patterns. `continue_landing` supplies the retained round baseline. Keep the first existing head/check/head query unchanged. Only a valid zero-check observation, with no previously observed registered check for that head, triggers evidence reads before the first sleep; bracket those reads with expected-head validation too. This preserves nonempty-check transcripts. A standalone helper call without a base has no exemption. Query failure, malformed CI or head/draft changes still refuse; evidence unavailable merely leaves ordinary waiting in place. Evidence reads, retries and polling consume the existing deadline, and deadline expiry is never swallowed as unavailable evidence.

6. **Require an actual registration opportunity.** Start a per-head timer at completion of the first head-bracketed empty poll. The exception needs a later validated empty poll at least `CI_POLL_INTERVAL` (10 seconds) later, with the shared budget still live. Accept either the existing exact missing-registration response or successfully validated exit-zero `[]`. Reuse `poll_sleep`; no new flag, deadline reset or poll after expiry. Any nonempty validated result, including skipped-only, permanently disables exemption for that expected head during this invocation, even if later results become empty. Pass/fail/pending/cancellation and inconsistent exit codes keep their normal meanings. A validated finish/update successor starts fresh proof and grace; a moved base starts another existing round. No proof or previous attestation is durable permission for a new head or invocation.

7. **Attest the decision separately and before merge.** Add `record_ci_attestation(identity, exclusion, operations)`, reusing the existing trusted-marker lookup, single-POST reconciliation and edit behavior through a small common comment-upsert helper. Use `<!-- nightshift:land-ci:<pr>:<head>:<base> -->`. The body starts with the existing Nightshift prefix and contains exactly `CI not required: docs-only`, actor, PR URL, full head/base SHAs, workflow path, patterns, changed paths and the observed grace interval. Resolve the authenticated actor even without listed checks; preserve Gitea's listed non-bot human requirement. Record this populated CI comment regardless of `--checks-done`, without asserting human-check completion or changing the existing pre-finish human attestation. Escape externally supplied text as the existing attestation does.

   After an exclusion result, revalidate landing inputs, persist the CI attestation within the shared budget, revalidate inputs again and perform the existing final base read. Print the exact reason only after the attestation is established. A base move repeats the round with fresh proof; the earlier comment remains a historical decision for its explicit head/base, not a claim that merge succeeded. Failure to identify the actor or establish a unique trusted attestation blocks merge. Sequential retries update the same marker; duplicate/untrusted matches refuse and ambiguous creates never cause a second POST in that invocation. Preserve the existing documented late-POST cross-invocation limitation. Successful green paths never create this comment.

8. **Preserve contracts and explain the precise exceptions.** The MODIFIED deltas qualify unconditional passing-check language in `Bounded CI wait`, `CI registration delay`, `Exact update provenance`, `Main movement restarts CI` and Gitea's combined CI requirement. The forge/compatibility deltas permit only additional missing-check evidence and exemption-attestation calls; existing argv and the relative ordering of existing gates remain intact. New regression fixtures may insert expected evidence reads returning unavailable data into existing empty-check scripts, but must not remove, relax or replace existing assertions or monkeypatch away the real polling gates. Nonempty-check transcripts remain byte-identical.

9. **Verification and operator guidance.** Task 1 tests pure matching and injected transports in `tests/test_land_ci_exclusion.py`. Task 2 tests complete landing through real policy helpers with fake clocks/runners/openers in `tests/test_land_docs_only.py`, including the three issue-named tests, late registration, missing evidence, deadline boundaries, head/base changes, finish successors and attestation recovery. Update `docs/landing.md` with supported syntax, grace/fallback, exact output, the separate CI marker and live-validation limits, citing issue #136. Retain its current human-check line rule `^[ \t>]*[-*+] \[( |x|X)\] ` unchanged, including matches in examples. If documentation checks select passages, use a unique exact column-zero heading through the next physical heading of equal or higher level; missing/duplicate headings block validation. Fences, HTML and indentation do not hide matching lines. Do not add prose-exact documentation assertions. Acceptance is `uv run pytest` green, existing assertions preserved, and no increase to the existing type baseline (`uv run python scripts/check_types.py`).

## Risks / Trade-offs

The narrow workflow grammar deliberately leaves some valid workflows on the existing timeout path. Supporting another YAML spelling or workflow layout later needs its own deterministic tests. File-list caps, missing rename provenance or unsupported Gitea metadata also decline the exception. Evidence is fetched after finish/update, so archive renames remain visible and do not reuse pre-finish paths.

The reason says docs-only because that is the intended `**.md` policy here; eligibility comes from the base workflow's explicit ignore patterns, not a hardcoded extension list. A repository owner who ignores another kind of file makes the same policy choice. Server protections can still reject a merge requiring a check that the workflow never schedules; landing does not override them.

No client can atomically bind a status read, comment write, base read and merge. A check can register after the final empty poll, and main can move after its final read. Observed registered checks always take the normal path; remaining races stay subject to forge protections. The shared budget includes the new reads/comment operations, so a very short timeout still refuses rather than skipping grace. Two tasks target roughly 300 changed implementation/test lines each by restricting workflow support and reusing existing transport/attestation machinery.

Human checklist for the implementation PR (not implementing-agent tasks):

- [ ] A human reviews and lands the next real Markdown-only PR with `land`; confirms no CI checks register, the grace is observed, output and the CI attestation contain `CI not required: docs-only`, and the attested head/base match the attempted merge.
- [ ] Inspect the resulting merge commit and protection outcome, recording the PR URL and merge SHA in the review record. If validating Gitea, also confirm live workflow filtering and human-token permissions. Offline CI cannot complete these live checks.
