## Context

`specloop/cli.py::_status_context` constructs `context.github` only for unqualified repositories or an explicit case-insensitive `github.com` host. It uses a nonempty saved PR as the existing publication signal, URL-quotes the repository and branch, and links to the parent of the resolved `task_path`. This also supports an archived change after partial finish. Other hosts currently receive an empty `github` string.

Prerequisite #129 supplies manifest forge selection through `_forge_target` and trusted `nightshift.config.parse_forges`; #138 carries design-level human checks into publication. Both are present in this clone. `_forge_target` loads bot credentials, so status must not call it. The status tests already forbid execution-context credential loading. No `AGENTS.md` was found in this clone; README, status code/tests and the `run-context`, `specloop-interface`, `specloop-forge` and `forge-configuration` requirements were consulted.

All existing requirements remain in force. The `run-context` requirement “Configured forge context links” governs Factory's handling of `context.github` and says that consumer work does not introduce producer fields. This change adds a separate producer requirement; it does not alter that consumer requirement or implement `link` consumption in the plugin.

## Goals / Non-Goals

Provide a usable change-folder URL for published runs on the configured Gitea backend, selected from the run's own manifest. Preserve the existing GitHub contract and all unrelated status output. Make construction and compatibility testable with temporary run repositories and local TOML fixtures.

Do not change publication, finish, admission, manifest syntax, credential policy, forge configuration semantics, Markdown parsing, plugin rendering, link allowlists or other forge backends. Do not edit `nightshift/` or `plugins/`. Also leave `KNOWN-LIMITATIONS.md`, `README.md`, `docs/specloop/README.md`, `specloop/manifest.py`, `specloop/verify.py`, `tests/test_loopback_docs.py`, `tests/test_loopback_evidence.py`, `tests/test_loopback_launch.py`, `tests/test_loopback_profile.py` and `tests/test_loopback_sandbox.py` untouched; these are owned by concurrent loopback work.

## Decisions

1. **Add only the non-GitHub field.** In `_status_context`, retain the existing GitHub calculation verbatim. For a manifest identity with three nonempty components and a host other than case-insensitive `github.com`, add string `link`; leave `github` empty. GitHub, empty-repository and existing generic error/fallback contexts acquire no new key. For a non-GitHub run without a saved PR, `link` is empty and forge configuration need not be read. Retain the existing saved-PR gate, including adopted PRs; do not query whether the branch was pushed or infer the forge from the PR URL or checkout remote.

2. **Resolve public URL metadata without credentials.** Add a small private helper in `specloop/cli.py`, for example `_status_forge_link(github: str, branch: str, task_path: str) -> str`. Follow `_forge_target`'s identity validation (`[HOST/]OWNER/REPO`, optional trailing slash, ASCII components, no `.` or `..`) for the new non-GitHub path. Select the config file from the process's nonempty absolute `NIGHTSHIFT_FORGE_CONFIG`, otherwise `config.DEFAULT_PATH`. Read TOML and call existing `config.parse_forges(raw)`; match exactly one `kind == "gitea"` definition by case-insensitive URL hostname. Preserve the configured scheme, port and installation prefix. Do not use manifest env files, `config.load_env_file`, `config.parse_env_file`, `_forge_target`, a forge client, `gh` or a remote request. Missing tokens do not affect display links. Leave publication selection untouched rather than refactoring its credential path for this small change.

3. **Use the backend's branch-view route.** For Gitea, build `definition.url.rstrip('/') + '/' + quote(owner_repo, safe='/') + '/src/branch/' + quote(branch, safe='/') + '/' + quote(Path(task_path).parent.as_posix(), safe='/')`. Preserve owner/repository case and slash-separated branches; quote reserved characters in appended path components. Do not quote the configured base again or drop its prefix. Example: manifest `forge.example/Owner/Repo`, base `https://forge.example:8443/git`, branch `spec/change`, and live task path produce `https://forge.example:8443/git/Owner/Repo/src/branch/spec/change/openspec/changes/change`. Use the resolved task directory for archives, never a guessed live directory.

4. **Isolate link failures.** Missing/unreadable/invalid config, a blank or relative override, invalid identity, unsupported kind, no matching host or multiple matching hosts yield `link: ""`. Catch these failures inside the new link helper so they do not trigger `_status_context`'s whole-context fallback. Never invent a GitHub URL or derive an origin from untrusted PR text. Preserve existing fallback behavior for unrelated context failures and existing error rows for core run-read failures. No new errors, diagnostics, state writes or status fields are introduced for a link failure.

5. **Test with real status assembly and no host application.** Add `tests/test_status_json_forge_link.py`, reusing the admitted-run fixture pattern from `tests/test_specloop_status_json.py` without changing existing assertions. Include `test_status_json_link_uses_run_forge`, parameterized over named/all-run queries, default/override config selection, two distinct configured hosts, and a mixed-case manifest host. Assert exact URLs including ports, prefixes and slash-bearing branches; include reserved-character quoting and an archived task-directory case. Assert GitHub contexts remain exact, unpublished links are empty, invalid/ambiguous configurations retain other context, and a healthy neighboring run survives. Use scenario markers for the delta scenarios. Compare preexisting status fields before and after adding a valid configuration, excluding only `context.link`, and snapshot state/events/refs to prove reads do not mutate runs. Make credential loaders and remote operations fail if called. Run the new tests, the existing status JSON tests, then `uv run pytest` with every existing assertion preserved.

## Risks / Trade-offs

- The lightweight selector repeats a small part of publication's configuration selection, avoiding credentials and changes to publication. Tests must pin identical host and config-path selection rules; no general forge-interface expansion is needed.
- A link cannot be constructed safely without a unique valid configured instance URL. Returning an empty link preserves status availability and avoids guessing ports or installation prefixes.
- Only the currently supported non-GitHub Gitea kind gets `/src/branch/`; another backend will need an explicit route mapping in its own change.
- A saved PR remains only the existing publication signal. CI can prove the emitted URL and read-only behavior, but not live branch availability, authentication or a phone's navigation behavior. Plugin support remains independently owned by #132.
