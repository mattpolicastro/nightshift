## Context

`plugins/nightshift/server/factory.ts` validates every PR before projecting the run list. Its GitHub-only check throws for a Gitea PR, causing a cold read to report unavailable or a refresh to retain a stale snapshot. `githubLink()` separately blanks non-GitHub context links. Both decisions need the same operator-controlled origin set.

`host-paths.ts` resolves trusted settings at execution time and preserves literal path spelling. Its current `{ cwd, uv, path }` return shape is asserted exactly by existing tests. `factory-landing.ts` uses separate status/start schemas from `shared/factory.ts`; those schemas already require canonical GitHub PRs. The client offers Land only for a matching non-stale offer. These boundaries must remain intact.

The current `run-context` display scenario explicitly drops every non-GitHub URL, so it needs a MODIFIED delta alongside the requested `paseo-runs-page` change. The producer requirement in `run-context/Context in status` stays unchanged: producing forge-aware status links belongs to #145. No `AGENTS.md` was present in this checkout or its searched repository subdirectories.

## Goals / Non-Goals

Display a published run from a configured forge without breaking the Factory section. Make trust explicit, local, exact by origin, reloadable, and testable with temporary files and fake status transport. Preserve cold errors, stale fallback, projection/redaction, action checks, and all current landing protections.

Do not change status JSON, CLI/worker validation, dependencies, client UI labels, remote forge discovery, or landing execution. Do not edit `specloop/`, `nightshift/`, `plugins/nightshift/server/reader.ts`, `README.md`, `docs/specloop/prepare.md`, `forge/gitea.py`, `forge/http.py`, or root `tests/`. New regression tests belong in new plugin test files. Existing tests and their assertions remain intact.

## Decisions

1. **Resolve the file through the existing host-path module.** Add `resolveForgeOriginsFile(env = process.env, home = homedir()): string` in `plugins/nightshift/server/host-paths.ts`. Share its literal path validation with the existing resolver without changing `resolveHostPaths()`'s return shape or validating the new setting for attention/landing/act consumers that do not read this file. Default to `~/.config/nightshift/forge-origins`; an explicit `NIGHTSHIFT_FORGE_ORIGINS_FILE` overrides it. Accept absolute paths and leading `~/`, preserve spaces/metacharacters and `..` literally, and do not evaluate variables or shells, normalize paths, probe existence, or create files. Reject blank, relative, unsupported tilde, NUL, CR and LF settings by name without exposing the value. A file path may contain a colon. Invalid path settings cause the ordinary sanitized unavailable/stale status response, rather than silently selecting another path.

2. **Read once per actual status load.** In `factory.ts`, resolve and read the file before executing `status --json`, obtaining one immutable allowlist for all rows and context links in that load. Read using Node built-ins; no network lookup or dependency is needed. Keep `createFactory(execute, clock, home)` callers compatible; an optional fourth server-owned loader parameter may provide a test seam, with production always using the real resolver/file reader. Do not accept configuration in RPC input. Preserve in-flight sharing, the 15-second throttle (including manual refresh), action invalidation and generation checks. A cached RPC read does not read the file or execute status; file edits take effect on the next actual status load without plugin restart.

3. **Use a deterministic, all-or-nothing file grammar.** Decode as UTF-8 and split on LF, removing a single terminal CR from each line for CRLF files. Ignore whitespace-only lines and lines whose first non-whitespace character is `#`. Treat every other whole line as an origin without trimming or removing inline comments. It is valid only when `new URL(line)` succeeds, its protocol is `https:`, and `url.origin === line`. Thus surrounding whitespace, paths (even `/`), queries, hashes, credentials, noncanonical spelling/default ports and inline comments invalidate the entire file. Duplicate valid entries are harmless. Canonical explicit nondefault HTTPS ports are allowed and remain part of origin matching. Start with `https://github.com`; add extra origins only after every line passes. Missing or unreadable files, or any invalid line, yield GitHub only, never partial acceptance or a previously cached list of extra origins. An empty/comment-only file also means GitHub only. Do not repair or rewrite the operator file.

4. **Extend PR and context projection narrowly.** Pass the single allowlist into `project()` and the context-link helper. For a nonempty PR, preserve the existing parsed GitHub `/^\/[^/]+\/[^/]+\/pull\/\d+$/` rule. For an allowed non-GitHub origin, require `/^\/[^/]+\/[^/]+\/pulls\/\d+$/`. In both cases reject credentials, query and hash. Compare complete `URL.origin` values, never host suffixes or prefixes; subdomains and other ports require their own entries. Adding GitHub to the file does not enable its `/pulls/` shape. Empty PRs remain valid. Any other PR still fails the entire status read using existing error/stale behavior; do not omit the offending row. For `context.github`, retain redaction and credential rejection while permitting HTTPS links on the same origin set. Context URLs keep their existing freedom of path/query/hash; they are not PR URLs. Invalid/foreign context links become empty strings without failing the read. Keep GitHub's existing context behavior and every schema/display-field restriction.

5. **Display trust does not grant Land eligibility.** Keep `factory-landing.ts` validating status offers, history/current records and start inputs through the existing GitHub-only schemas, including revalidation after redaction. Do not route those checks through the display allowlist or broaden `shared/factory.ts`. If an explicit server guard is needed, put it in `factory-landing.ts`; preserve existing validation outcomes. A configured Gitea PR with human-check metadata receives no usable Land offer; a forged non-GitHub confirmation never reaches private `start`. Retained GitHub offers cannot match a run whose PR changed to Gitea. Preserve independent landing caches, history, Stop, pause/head identity checks and literal transport. Tests may establish that existing guards already satisfy this behavior without a redundant production edit.

6. **Verify offline in two sessions.** Add `plugins/nightshift/tests/factory-forge-origins.test.ts` for file/path integration, PR/context allowlisting and failure behavior, and `plugins/nightshift/tests/factory-forge-landing.test.ts` for landing eligibility using existing fixtures/model or rendered harness. Include the exact test titles `accepts configured forge links`, `rejects foreign origins`, `invalid origins file allows GitHub only`, and `land offered only for GitHub links`; attach scenario-ID parent tests/subtests as appropriate. Use temporary files, isolated environment overrides restored after each test, fake clocks and injected command results. Exercise production file loading as well as any pure parser. Preserve every existing assertion. Acceptance is `cd plugins/nightshift && npm test && npx tsc --noEmit`.

## Risks / Trade-offs

- An allowlist typo deliberately revokes all extra origins. A run using one then makes a cold snapshot unavailable or a refresh stale, matching today's validation boundary. Missing/unreadable files do not make otherwise valid GitHub reads fail.
- Revocation is observed on the next uncached read. Existing stale tolerance may continue displaying a previously accepted link in a clearly stale snapshot; this change does not introduce cache purging or immediate revocation.
- The legacy `context.github` field and its GitHub-labelled navigation remain unchanged, even for an allowed forge destination. Renaming them or emitting a generic status `link` belongs to separate work.
- Broadening ordinary display does not establish that Publish, Finish or Land supports a forge. Land remains GitHub-only until #130.
- Automated tests prove parser, server and model/rendered behavior without Paseo or a live forge. They cannot prove the installed phone integration. **Human PR checklist:** on the phone, with a real published Gitea run present in the host's run directory and its exact origin configured, verify the Factory section loads, the run's PR link opens the correct PR, and its row has no Land button. Record the outcome; this is not an implementing-agent task.
