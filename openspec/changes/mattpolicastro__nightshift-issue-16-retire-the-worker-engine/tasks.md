## 1. Retire the worker engine atomically

Implement in numbered order in one change/PR. Do not deploy intermediate commits. Each range estimates total added plus deleted lines, including tests, fixtures and import cleanup; approximately 300 is the maximum, not a source-only allowance. Boundaries are fixed now because implementing agents cannot edit openspec/**. Retire tests only for the exact removed contract named here and in `design.md`; shared behavior remains protected.

Every task runs uv run pytest and the applicable type check. Retained-contract migrations precede deletions and pass against intermediate and final code. Replace worker-only progress assertions with actual specloop progress, never skipped tests, permissive monkeypatches or no-op stubs. Run `uv run python scripts/check_types.py` only in check mode; never use `--update` or edit `mypy-baseline.txt`. Resolved/deleted diagnostics may remain because the checker rejects only new diagnostics. Implementation edits are limited to `nightshift/**`, `specloop/**`, `tests/**`, `README.md`, `KNOWN-LIMITATIONS.md`, `config.example.toml` and `docs/specloop/**`; all other paths remain unchanged. In particular, do not edit frozen wrappers/plists, plugin files, CLAUDE.md or pyproject.toml. Line references identify this drafting checkout; symbols and test names are authoritative.

Documentation tasks use existing TOML/CLI/link checks. For any new rich-text structural check apply `design.md`'s literal raw-line rule and block on ambiguity; do not parse fences, HTML or indentation semantically. Live config, installed plists and external scripts are exclusively the PR human checklist.
