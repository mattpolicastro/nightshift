## Context

`specloop/openspec.py::_run` launches the pinned OpenSpec CLI once with `timeout=120`, parses stdout as JSON, and currently turns invalid JSON into `SpecError`; `TimeoutExpired` escapes unconverted. Admission's `_admit_locked` catches broad exceptions as refusals, and the JSON dispatcher defaults exceptions from drafting to rejection. `problems_with` and `propose.lint` also convert `SpecError` from scenario discovery into validation problems.

The existing daemon client treats a top-level `error` as an item failure. `nightshift/daemon.py::item_failed` retains triggers, retries on later eligible polls and escalates at its configured threshold. No daemon changes are needed. #174 is the prerequisite; its source-clone behavior remains intact. No `AGENTS.md` is present in this checkout.

`openspec/specs/spec-critic/spec.md` currently requires preserving all pre-critic retries under `Ordered proposal gates`. A no-JSON registry failure in `openspec.scenarios` currently becomes a lint problem in `propose.lint`, then correction feedback in `propose.draft`. Forwarding the new subclass deliberately changes that behavior, so this change includes a matching MODIFIED delta rather than silently breaking the retry guarantee.

## Goals / Non-Goals

Make temporary OpenSpec unavailability distinguishable from invalid specs at the admission and drafting boundary. Keep every existing `except openspec.SpecError` runtime fallback working and keep evidence failures closed. Fit classification, exception routing, documentation and tests in one session targeting about 150 implementation lines.

Do not retry within `_run`, admission validation or drafting lint; a transient failure must also escape the draft-correction loop. Do not change timeouts, validation rules, normal drafting corrections, publication, daemon eligibility/thresholds or runtime callers. No new Markdown or HTML parsing is required.

## Decisions

1. **Exception and classification.** Define `class ValidatorUnavailable(SpecError)` in `specloop/openspec.py`. Catch `subprocess.TimeoutExpired` around the existing single subprocess call and raise the subclass with a useful command/timeout diagnostic and the original exception as its cause. Keep the pinned package, argv, environment and 120-second limit. In the existing `JSONDecodeError` branch, classify stderr containing a standalone, case-sensitive code from `ENOTFOUND`, `ETIMEDOUT`, `ECONNRESET`, `EAI_AGAIN`, `ECONNREFUSED` as unavailable; use token boundaries so longer identifiers do not match. Inspect stderr before its existing 400-character diagnostic truncation. All other no-JSON results remain plain `SpecError`. Parseable JSON takes precedence even when stderr includes one of these codes; leave `validate`'s problem extraction unchanged.

2. **Narrow admission/drafting forwarding.** In `specloop/cli.py::problems_with` and `specloop/propose.py::lint`, catch `ValidatorUnavailable` before `SpecError` and re-raise it, including when validation's scenario-discovery call is unavailable. Do not turn it into a problem string or correction feedback. In `_admit_locked`, intercept it before the broad refusal catch, retain `_clear_admission` cleanup and re-raise without saving admitted state. The existing CLI JSON exception path must recognize this subclass only for `admit`/`propose` validation and replace the default document with exactly `{"version": 1, "error": "..."}`, returning 1. This minimal forwarding through the current broad wrappers is part of the validate-call change; it does not change how other exceptions or commands are handled. Preserve non-JSON nonzero failure behavior and stdout/stderr separation.

   The `Ordered proposal gates` delta makes this the sole new exception to existing pre-critic correction retries: a validator outage during lint, including scenario discovery, exits the attempt before feasibility, PR-file lookup or critic review for that candidate. It also escapes lint during a critic correction without spending another round. Plain `SpecError` scenario-discovery failures still become lint problems, and ordinary lint/feasibility failures keep their existing retry budget and feedback. Both original gate scenarios are retained, with the earlier-gate scenario explicitly qualified for ordinary failures. No changes to the drafting loop or critic implementation are needed.

3. **Compatibility by inheritance.** `_run` is shared by validate, show and archive. Using a subclass, never a sibling exception, keeps `loop._scenario_text`'s diagnostic text, `loop._gate_context`'s `gate_scenarios_failed` event and existing evidence-gate failure handling intact. Those modules remain untouched. Successful validation and JSON containing real problems follow existing paths. Unrecognized no-JSON failures retain plain `SpecError` and the current refusal/rejection behavior.

4. **Recovery belongs to later polls.** Emit no new outcome or retry hint. The daemon already understands the error envelope, retains `spec:approved` or intake/arming labels and counts the item failure. Repeated failures can reach its existing threshold and add `needs-human`; that label holds further retries until removed. Authorization, head binding, pause, stopped-job and other eligibility gates remain authoritative. There is no immediate rerun, backoff or three-call 363-second budget.

5. **Document the exception without widening publication behavior.** Extend only the existing exception paragraph in `docs/specloop/command-json.md` with transient validator failures for `admit`/`propose`, exit 1, no `outcome`, retained triggers, later eligible polls and existing holds/thresholds. Preserve the command table, publication exception and ordinary proposal-publication failure behavior. The spec deltas explicitly narrow the old general non-success promise; no unrelated guarantee is removed.

   Select that paragraph by the unique physical line starting exactly `Publication exceptions (` and end it at the next blank physical line. Missing or duplicate starts, or no terminating blank line, block the edit for inspection; do not infer Markdown fences, HTML or indentation semantics.

6. **Deterministic verification.** Use mocked subprocess timeout/completion results and existing local repository/CLI fixtures, without sleeping, contacting npm or running live agents. Add `test_validator_timeout_is_transient_not_refusal` (also assert `isinstance(error, SpecError)`, one subprocess call and `timeout=120`), `test_validator_registry_failure_is_transient` parameterized over all five codes, `test_admit_validator_unavailable_emits_error_envelope`, `test_propose_validator_unavailable_emits_error_envelope`, and `test_real_validation_failure_still_refuses`. Exercise actual command routing, not a stub that manufactures the final document; inject unavailability at both validate and scenario-discovery boundaries. Check exactly one JSON document, nonempty `error`, no `outcome`, exit 1, admission cleanup and no draft correction/publication after unavailability. Add compact negative cases for unknown no-JSON errors, code-like substrings and valid JSON problems with network-looking stderr. Parameterize the existing feedback-scenario fallback/fail-closed tests with the new subclass while preserving every assertion. Reuse existing successful proposal and needs-input tests. Require `uv run pytest` and `uv run python scripts/check_types.py` to pass with no new type errors or baseline weakening.

   Cover the amended critic gate with the same proposal-envelope test: with drafting rounds remaining, raise `ValidatorUnavailable` from scenario discovery and assert one drafting write and no subsequent feasibility, PR-file lookup, critic or publication calls. Parameterize a compact ordinary-failure control with plain `SpecError`: it must still reach correction feedback and another drafting attempt. Reuse `tests/test_specloop_critic_propose.py`'s clean-candidate, lazy-context and earlier-gate-retry tests unchanged to verify preserved gate order and ordinary lint/feasibility corrections; no separate integration framework or new critic behavior is required.

## Risks / Trade-offs

- The fixed code list intentionally leaves other npm failures as ordinary errors. Broad heuristic classification would conceal real validation/tool failures; extending the list is future work.
- A subclass changes timeout handling in shared callers from an unconverted exception to their established `SpecError` fallback. Regression coverage must protect diagnostic text/events and evidence failure behavior without editing their owners.
- One subprocess call can still consume 120 seconds, and other admission work can still exceed background deadlines. This removes retry amplification; it does not promise a whole-command deadline or bypass eligibility holds.
- The approximately 150-line implementation budget relies on existing fixtures and parameterization, retaining all existing assertions. Avoid a new integration framework or daemon test matrix.
- **Human check after deployment:** CI cannot prove recovery from a real registry stall. The next time validator timeout logs appear, confirm the approval survived the failed attempt and the unchanged change proceeded on a later eligible retry. If the failure threshold was reached, inspect the retained trigger and existing `needs-human` hold before retrying. This operational observation is not an implementation task.
