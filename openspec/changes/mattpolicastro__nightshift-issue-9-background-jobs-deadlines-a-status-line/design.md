## Context

`specloop_job.start()` writes `{ "args": ... }` before launching a detached wrapper. The inherited lifetime lock survives daemon restart; `process.json`, `control.lock` and stop intent protect owned-group termination. Collection returns pending while the lock is busy. Intake persists results and delivers them through four paths: initial proposal, admission, spec revision and build revision. Admission currently reconstructs its receipt and drops `job`; proposal recovery through an existing PR can finish without recording delivery on a matching receipt.

`daemon.poll_specloop()` immediately escalates `DeliveryError`; other failures use health thresholds. `report_failure()` uses `<stage>-error` markers, but `queue._reconcile_intake_comment()` recognizes only draft/admit/publish/revise. Its production retry can repeat a remotely successful POST after HTTP 502. Approval markers have the same gap.

`touchpoints.py` reads retained request args for command/change/head, the adjacent result for round outcomes, and the earliest proposal request mtime for date selection. Deleting directories or changing those mtimes loses history after receipt replacement. `--idea-file` already keeps new idea text out of argv; older requests can still contain inline idea text. Workflow receipts retain idea/feedback snapshots needed for later revisions.

The stop/release, pause, authorization, configuration-health, feedback-consumption and touchpoint requirements remain in force. No AGENTS.md exists in this checkout or its applicable ancestor locations; the repository's referenced `CLAUDE.md` constraints were read. This is a spec-only draft; implementation is restricted to the scope in proposal.md.

## Goals / Non-Goals

Make hung work actionable, make active work visible, reclaim delivered logs and drafting payloads, and prevent timed-out daemon git commands leaving ordinary transport descendants alive. All behavior should be testable locally with controlled clocks, persisted fixtures, fake GitHub transport and real disposable subprocess groups.

Do not change worker scheduling, health thresholds, label authorization, stopped-job release, feedback selection/consumption, remote reconciliation policy, admission-head binding or supervisor semantics. Do not add a sweeper that guesses delivery from age, process exit, current labels or a successful result. Do not claim a privacy purge: receipts, results, build feedback and stopped evidence remain.

## Decisions

### 1. Persist command timing once

In `nightshift/specloop_job.py`, add `COMMAND_TIMEOUT_SECONDS = {"propose": 3600, "admit": 300, "revise": 1800}` and a clock seam for tests. `start()` persists exactly `stage`, `args`, `started_at`, `timeout_seconds`, and `deadline_at` before launching. Stage is the containing inventory stage (`proposals`, `admissions`, `revisions`); args remain exact until delivery. Times are finite numeric UTC epoch seconds; timeout is positive and deadline equals start plus timeout. Propose has the same budget in proposals and spec revisions. The budget includes wrapper startup and is never reset by polling or restart.

Extend `Job` with optional timing fields and read them through a common validator. Missing timing in a legacy request remains supported, with no inferred deadline or write-on-read migration. A compacted legacy request may carry three null timing fields. Partial, non-finite, boolean, inconsistent timing or a mismatched stage produces a diagnostic without hiding healthy rows. Unknown fields remain tolerated. Inventory never runs `ps`, launches commands or changes files. Clamp displayed elapsed time to zero after backward wall-clock movement; wall-clock changes can affect deadline observation and are an explicit limitation.

Migrate `tests/test_specloop_jobs.py:test_restart_inventory_all_stages_history_and_order` (formerly line 112) from exact `{args}` equality to exact equality with the complete five-field schema using a controlled clock. Keep exact args, persisted identity, deterministic order, legacy and offline/no-subprocess assertions.

### 2. Escalate overdue pending work through existing intake

Inside collection, check stop intent first, then the lifetime lock. If the attempt is still live and `now >= deadline_at`, raise a typed `JobOverdue` containing job ID, command, elapsed/budget and log location, without detaching its receipt or changing execution state. Intake `_collect()` maps that exception to `DeliveryError`, preserving immediate escalation in the existing daemon callback without changing its thresholds. Before deadline use the normal pending callback. An idle attempt with a completed result is collected normally even if its deadline passed; an idle attempt without a result keeps existing crash handling. A late result may be delivered after the operator resolves the `needs-human` hold under normal eligibility.

Deadline is a reporting threshold, not automatic process termination. Hung work keeps its job ID so operators can pause, stop, inspect and release it. The failure detail includes this recovery guidance. Pause and failed/denied authorization withhold collection and external escalation just as today; resume or restored authorization detects an expired deadline without extending it. Stopping/stopped work never escalates for age. A removed trigger, stopped daemon or unavailable GitHub can delay reporting; local status still exposes expiry.

Retain the existing error comment marker and label-last ordering. A failed comment or label write leaves the job attached and retryable on the next eligible poll, including after restart. Extend the regex only to `(?:draft|admit|publish|revise)(?:-error)?|approval`, retaining its anchored marker body syntax. Test `report_failure()` with the real `queue._gh` retry loop and a mocked subprocess transport that stores a POST then returns HTTP 502; verify one comment, later-page lookup and PATCH. Cover all four error actions and approval markers, a failed reconciliation read preventing blind POST, existing completion markers, and inherited pause guards. Do not substitute an in-memory `_comment()` stub for these checks.

### 3. Render local active work in status

In the status branch of `nightshift/cli.py`, call `list_jobs(daemon.STATE_DIR)` once and print active rows before repository network queries. Keep inventory order and include jobs from no-longer-enrolled repositories. Display full ID, stage, repository/item, command name, execution state, elapsed seconds, and remaining seconds or `OVERDUE by Ns`. Starting/legacy rows show unavailable timing explicitly. Starting, running and stopping rows are active; finished/failed/stopped history remains in `nightshift jobs`. Never render full argv or idea text.

Keep heartbeat/liveness, alerts, worker rows, configuration loading, default status invocation and exit behavior unchanged. Show inventory diagnostics alongside good rows without turning the status command's existing success return into a new failure policy. `nightshift jobs` keeps its existing diagnostic exit codes. Empty inventory adds no line. Inventory/status reads cannot perform cleanup or deadline escalation.

At `tests/test_jobs_cli.py:test_existing_commands_and_options_remain_compatible` (formerly line 257), allow and assert a single empty inventory read only for `[]` and `["status"]`; keep it forbidden for the other commands and preserve all option, loading, output and exit assertions.

### 4. Compact a delivered attempt, preserving history

Add `compact_delivered(path, receipt)` in `specloop_job.py`. It accepts an exact matching job-bearing delivered receipt with a valid terminal result. Acquire locks in the existing order: attempt control lock, optional existing receipt-release lock, then a nonblocking lifetime-lock check. Reread identity and state under coordination; do not create a release lock. Refuse stop intent, a busy lifetime lock, mismatched/replaced receipts, missing or malformed records, or symlinked evidence. Never use `rmtree` or remove locks.

Before altering artifacts, atomically save an attempt-local `cleanup.json` journal with version 1, the exact job ID/stage/item context, original request atime/mtime in nanoseconds, the normalized idea-file deletion target when safe, and `complete: false`. It contains no idea text. This journal certifies a previously authorized, durably delivered matching attempt and survives receipt replacement. Capture timestamps before rewriting the request. Persist a minimal five-field request: stage, args minus `--idea VALUE`, `--idea=VALUE`, `--idea-file VALUE` or `--idea-file=VALUE`, and the original timing fields (null for a timing-free legacy request). Preserve every other argument, particularly command, change, branch, head and build-feedback references.

Set the temporary request's original timestamps with `os.utime(..., ns=...)` before atomic replacement, so no published replacement acquires today's mtime. Retain `result.json` byte-for-byte, process/stop/collection metadata, lifetime/control locks and the job directory. Remove only `log` and the exact owned idea file. File input may be a sibling under the item's `.jobs` directory; require a regular non-symlink file inside that root, uniquely referenced by this attempt. Never follow or delete an outside path, a shared file, a directory or a symlink; retain it with a diagnostic. Inline idea arguments can be redacted without deleting a file. Leave `--feedback` JSON files, workflow receipts, unknown artifacts and stopped/released attempts untouched. Mark the journal complete only after successful compaction; missing already-deleted files are idempotent success.

The originally requested `test_finished_job_directory_removed` retains that test name for acceptance compatibility, but asserts removal of heavy delivered artifacts and survival of the directory, minimal request, result and readable inventory. Whole-directory deletion is explicitly superseded by the user's history-retention answer.

### 5. Integrate once at each delivery boundary

Add a shared intake `_finish_delivery(path, receipt)` that atomically saves `delivered: true` using the existing identity coordination, then invokes compaction. Use it for proposal outcomes, matching existing-open-PR recovery, admission admitted/refused outcomes, and both revision modes. Domain refusals/questions are terminal delivered outcomes; pending, wrapper failure, failed notification, paused, unauthorized and stopped attempts are not cleanup candidates.

Carry the original job reference through admission receipt reconstruction only when it belongs to the same change, approval event and selected result; preserve its original head for committed-admission notification recovery. Do not attach an earlier attempt to a colliding run or newer approval. Proposal PR recovery may mark a receipt delivered only when the receipt's validated result and recorded change/branch identify the recovered PR; recovery without matching local evidence does no cleanup. Result validation and existing authority/head checks still precede delivery.

Revision delivery must acknowledge only the saved selected IDs at the existing success boundary, before notifications. Cleanup happens after comments, applicable label changes and delivery persistence. It must preserve consumed IDs, unknown receipt fields, round markers, saved feedback, newer label applications and all build-feedback files. Keep injected synchronous `specloop_runner` behavior: without a durable job identity, there is no compaction candidate and its files remain. Do not invent background records solely for test doubles.

Narrow test migration: in `tests/test_specloop_label_authorization_recovery.py:test_untrusted_reapplication_holds_running_and_finished_job_and_its_payload`, replace the trusted-delivery whole-request equality and payload-read assertions (formerly lines 533–534) with exact minimal request identity/args/timing, unchanged request mtime, result/control retention and absent delivered idea input. Keep authorization-denial snapshots at lines 518–525 exactly as they are. Any other post-delivery background-input assertion affected by this explicit policy gets the equivalent replacement; all pre-delivery, stopped/released, delayed-reader and synchronous-injection input assertions remain.

### 6. Resume interrupted cleanup without redelivery

Add local cleanup recovery in intake, invoked at each stage entry on unpaused polls, independently of currently armed GitHub items. It scans that stage's valid delivered job-bearing receipts to seed missing journals, and existing incomplete journals to resume work. This recovers a crash after delivered-receipt persistence but before journal creation, even when the final label removal made the item disappear from the queue. Existing journals require their own immutable attempt identity/result and idle unstopped state; a newer parent receipt is neither modified nor used as proof for an older attempt.

Before replacing a delivered job-bearing receipt with a new round, ensure its cleanup journal has been durably created; if journal creation fails, defer replacement and report the local diagnostic. Once the journal exists, a cleanup unlink failure need not block new work: retries use that journal independently of the newer receipt. Legacy delivered receipts with no job ID are not guessed into cleanup candidates. Unproven orphan attempts remain retained. No cleanup scan calls GitHub, alters labels, counts a delivery failure or reruns completed work. A paused scan is withheld; status is always read-only. Retry filesystem failures with diagnostics on subsequent polls, never as a new job or human escalation.

Tests inject failure before/after journal creation, after request replacement, during unlink and before completion persistence; restart with cleared in-memory handles and rearmed/replaced receipts. Verify original mtime, older/newer result isolation, no duplicate delivery, no mutation of denied/undelivered or stopped evidence, and independent progress for healthy items. These recovery tests are a separate task from delivery integration to fit the session ceiling.

### 7. Bound daemon git process groups at the actual injection point

Preserve the currently used subprocess argument, output and check semantics. On `TimeoutExpired`, send SIGKILL to `child.pid` as PGID, tolerate an already-gone group, reap the child and bound post-kill draining to one second; close remaining pipe handles rather than wait forever for an escaped descendant. Re-raise the timeout for `_bounded_run`'s existing retryable error translation. Propagate signalling failures with a diagnostic rather than reporting successful termination.

`_bounded_run` selects `run_git` by default for git argv, otherwise retains its subprocess runner. Keep explicit injected runners and the existing `POLL_COMMAND_TIMEOUT = 30`. In `daemon.poll_specloop`, change only `git = guarded(subprocess.run)` to `git = guarded(specloop_intake.run_git)`; preserve the immediate pause guard. Publish's specloop invocation, GitHub transport, status calls and worker git are unchanged.

Migrate git doubles in `tests/test_specloop_approval.py` (147 and 315), `test_specloop_spec_revision.py` (163–175), `test_specloop_isolation.py` (147), `test_specloop_timeouts.py` (51–63), `test_specloop_background.py` (299 and other git interceptors), and `test_specloop_idea_file.py` (48) to `specloop_intake.run_git` or an explicit `git_runner`. Audit other git-specific `subprocess.run` patches. Keep separate gh/ps/status mocks at their current seams, and preserve behavioral assertions for admissions, revisions, authorization, pause, delivery, heartbeat/harvest and worker progress. Mocks should fail on unexpected git so nonexistent fixture repositories never reach real git accidentally.

Keep separate real-runner tests using a temporary fake git executable which spawns a transport grandchild, signals readiness through a pipe/file and blocks. `test_git_timeout_kills_process_group` proves both cease executing while an unrelated session survives. Use unique tmp paths, bounded readiness waits, and independent finally teardown of every created group and reaping, even if the tested runner fails; no global process names, live origin or fixed startup sleeps. Test normal/nonzero return, output capture and `check=True` as well as timeout.

## Risks / Trade-offs

- Eight tasks exceed the normal six-task target because cleanup recovery and delivery integration have different crash/authorization boundaries. Combined proposal/admission/revision hooks use one helper and parameterized tests; each task targets at most roughly 300 changed lines including tests. Split further only if measured implementation size requires it; do not omit matrix cases to hit a line target.
- Deadline reporting is poll-driven and requires authorized eligibility and available GitHub; it is not a watchdog while the daemon is stopped. Conservative fixed defaults may need future tuning. Clock jumps affect elapsed calculations.
- Minimal records still accumulate. Logs disappear after delivery, but results, receipts and build feedback may contain text; this is neither total garbage collection nor secure erasure. Stopped evidence remains unbounded by design.
- Request mtime preservation is required for compatibility, not a better date model. Missing preexisting history and unsupported filesystem failures remain report limitations. Atomic temp replacement plus pre-publication `os.utime` prevents an interruption exposing a new draft date.
- Git group kill is POSIX behavior. Remote push acceptance can precede timeout, and descendants that create a new session escape the group. Existing reconciliation and ambiguous-outcome retry remain necessary. Background-job stop groups remain separate from daemon git sessions.

Implementation acceptance is `uv run pytest` green, including `test_hung_job_escalates_after_deadline`, `test_finished_job_directory_removed`, `test_git_timeout_kills_process_group`, `test_error_comment_retry_does_not_duplicate`, and `test_cleanup_preserves_touchpoint_history`. Run applicable type checks without expanding the baseline; no live service is needed for automated acceptance.

Human checklist for the implementing PR (not agent tasks): on a disposable macOS setup, stall a real origin during fetch/push, observe git/transport PIDs and daemon responsiveness, and inspect remote refs before retrying; CI cannot prove real stalled-origin behavior or what a remote accepted. Exercise an overdue detached job with pause/resume and inspect the status/recovery text. Check the three updated operator passages together for readability and verify issue/PR references. Keep unperformed live checks explicitly pending and retain the independent-supervisor/committed-effect caveats.
